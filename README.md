# 🧸 Kids Game Mobile Paywall — Nuxt 4 + TypeScript

Полнофункциональный мобильный экран оплаты (Paywall) для условной детской развивающей игры компании **AmayaSoft**.

Проект выполнен в соответствии с тестовым заданием: нарисован мобильный макет, реализован fullstack-сервис на **Nuxt 4 + TypeScript**, написаны серверные маршруты для тарифов и покупок, подключена персистентная база данных, проработаны состояния загрузки, ошибок, успеха и восстановления покупок. Вёрстка выполнена mobile-first с точностью до пикселя (Pixel Perfect 99%).

## 🚀 1. Как запустить проект локально

### Предварительные требования
- **Node.js**: v18.18+ или v20+ / v22+
- **Пакетный менеджер**: `pnpm` (рекомендуется) или `npm`

### Быстрый старт
```bash
# 1. Клонировать репозиторий или перейти в папку проекта
cd kids-paywall-nuxt

# 2. Установить зависимости
pnpm install
# или npm install

# 3. Запустить режим разработки
pnpm dev
# или npm run dev
```

Приложение откроется по адресу: **`http://localhost:3000`**

> **База данных из коробки**: Локально проект использует встроенный SQLite (`file:paywall.db`). Никаких Docker-контейнеров, миграций или внешних сервисов настраивать не нужно — таблица `purchases` создается автоматически при первом обращении.

### Продакшн сборка и проверка
```bash
# Сборка проекта
pnpm build

# Локальный запуск продакшн сервера
node .output/server/index.mjs
```

## 🗄 3. Какую платформу деплоя и БД выбрали и почему

### База данных: SQLite / LibSQL с автоматической адаптацией под Serverless
- **Почему LibSQL / SQLite**:
  1. **Универсальность**: один и тот же клиент `@libsql/client` работает локально с файлом `file:paywall.db` без сетевых задержек, а при подключении облачной базы (Turso) — через `DATABASE_URL` по протоколу HTTP/WebSockets.
  2. **Serverless-ready**: на Vercel движок автоматически направляет локальное файловое хранилище в директорию `/tmp`, обеспечивая стабильную работу бессерверных функций без сбоев прав доступа `EROFS`.
  3. **Легковесность**: компактная схема (`offerId`, `deviceId`, цена, валюта, статус, дата/время) не требует тяжелых ORM вроде Prisma, что обеспечивает мгновенный холодный старт (Cold Start < 50ms).

### Платформа деплоя: Vercel
- **Почему Vercel**:
  1. **Нативная поддержка Nuxt 4 и Nitro**: движок Nitro автоматически определяет окружение Vercel и собирает оптимизированные Serverless Functions без ручной настройки конфигураций.
  2. **Полноценная работа серверных маршрутов (`/api/*`)**: все эндпоинты (`/api/offers`, `/api/purchase`, `/api/restore`) функционируют как независимые бессерверные API-эндпоинты с быстрой обработкой запросов.
  3. **Автоматический CI/CD и Edge Network**: мгновенный деплой по пушу в ветку `main`, автоматический SSL-сертификат, глобальный CDN для статических ассетов и шрифта Nunito с минимальным TTFB.

## 🤖 4. Какие AI-инструменты использовали и что проверили сами

### Использованный AI-инструмент:
- **Google Antigravity** на базе модели **Gemini 3.8 Flash**.

### Базовая роль AI:
- Первичная кодогенерация каркаса компонентов на Vue 3 Composition API (`<script setup>`, TypeScript).
- Написание основы серверных маршрутов Nitro (`/api/offers`, `/api/purchase`, `/api/restore`) и схемы инициализации таблицы покупок.
- Генерация первичных SVG-векторов (маскот мишки и иконки преимуществ).

### Что проверено и доработано мной лично:

1. **Синхронизация макета Figma и вёрстки (исправление артефактов генерации)**:
   - Изначально сгенерированный нейросетью векторный макет при импорте в Figma имел расхождения: слетали шрифты (подставлялся дефолтный системный Arial вместо Nunito), съезжали базовые линии надписей и нарушалась геометрия карточек.
   - Провёл детальное ревью макета относительно живой вёрстки: пересобрал векторные слои, нормализовал типографику, выровнял отступы и зафиксировал аккуратную структуру групп в Figma для обеспечения честного Pixel Perfect (99%).

2. **Продуктовая локализация и UX под реальный рынок (устранение технических шаблонов)**:
   - **Нейминг тарифов**: сгенерированный абстрактный англицизм *«Premium Pass»* заменил на привычный и понятный родителям *«Полный доступ»*.
   - **Клиентский чек**: модальное окно успеха изначально содержало сырой технический `uuid` заказа, статус `completed` и внутренний `deviceId`. Для пользователя это информационный шум, поэтому чек был переработан в понятный вид: *«Номер заказа: № 1»* и статус *«Активирована»*.
   - **Платежная инфраструктура**: скорректировал концепцию оплаты. Предложенные нейросетью Apple IAP и Google Play Billing в РФ недоступны, поэтому архитектура была адаптирована под универсальные сценарии: СБП (Система быстрых платежей / СБПэй), T-Pay, SberPay, карты МИР и RuStore.

3. **Комплексное тестирование фавиконов и QR-шеринга (Edge Case)**:
   - При проверке деплоя на Vercel и тестировании сценария открытия страницы через QR-код со смартфона обнаружил, что браузеры подставляют в центр QR-кода дефолтный логотип Nuxt либо отдают 404 по `/favicon.ico`.
   - Локализовал проблему: в проекте отсутствовала папка `public/` со статическими иконками. Разработал и подключил брендированный комплект фавиконов (SVG с мягкой подложкой для тёмной/светлой темы, классический ICO и Apple Touch Icon), после чего отображение в QR и вкладках стало единообразным.

4. **Обеспечение стабильности Serverless-хранилища**:
   - При деплое на Vercel учёл специфику бессерверной файловой системы (read-only filesystem `EROFS`). Добавил логику автоматического переключения пути SQLite в доступную для записи директорию `/tmp/paywall.db` при обнаружении serverless-окружения, что гарантировало стабильное сохранение и восстановление покупок в демо.

5. **Очистка репозитория от черновых артефактов**:
   - Удалил временные скрипты с локальными путями macOS, исключил служебные файлы `.npm`, настроил правила в `.gitignore` и актуализировал юридические тексты (соответствие 152-ФЗ и COPPA).

## ⏱ 5. Что бы сделали следующим шагом, если бы было ещё 2 часа

Если бы на задачу было выделено ещё 2 часа, я бы реализовал:
1. **Интеграция с нативным WebView (JSBridge) и универсальный платёжный роутинг**:
   - Двустороннее общение с хост-приложением (WebKit MessageHandler для iOS / JavascriptInterface для Android).
   - **Адаптивные сценарии оплаты**:
     - **Для рынка РФ**: бесшовная оплата и автопродление подписок в 1 клик через **СБП (Система быстрых платежей / СБП Подписки)**, интеграция с **T-Pay / SberPay**, приём карт МИР через эквайринг (ЮKassa / CloudPayments), а также нативный SDK **RuStore In-App Purchases** для Android.
     - **Для международной аудитории**: автоматическое переключение на StoreKit / Google Play Billing при соответствующей геолокации и валюте.
   - Тактильный отклик (Haptic Feedback) через Web Vibration API или нативный мост при выборе тарифов.
2. **A/B тестирование (Remote Config)**:
   - Возможность динамически менять порядок тарифов, тексты бейджей («Скидка 70%» vs «3 дня бесплатно») и цвета CTA-кнопки по параметру конфигурации из базы данных.
3. **Родительский контроль (Parental Gate)**:
   - Всплывающее математическое или логическое задание для родителей («Решите: 12 + 7») перед переходом к экрану оплаты, как того требуют стандарты безопасности детских сервисов (COPPA, Kids Safety Guidelines).
4. **Интернационализация (i18n)**:
   - Добавление локалей (EN, ES, DE, JA, ZH) с автоматическим форматированием валют (`Intl.NumberFormat`).
5. **E2E и компонентные тесты (Playwright / Vitest)**:
   - Автотесты полного пользовательского сценария: выбор тарифа $\to$ клик CTA $\to$ валидация записи в БД $\to$ отображение модалки успеха.
