# 🧸 Kids Game Mobile Paywall — Nuxt 4 + TypeScript

Полнофункциональный мобильный экран оплаты (Paywall) для условной детской развивающей игры компании **AmayaSoft**.

Проект выполнен в соответствии с тестовым заданием: нарисован мобильный макет, реализован fullstack-сервис на **Nuxt 4 + TypeScript**, написаны серверные маршруты для тарифов и покупок, подключена персистентная база данных, проработаны состояния загрузки, ошибок, успеха и восстановления покупок. Вёрстка выполнена mobile-first с точностью до пикселя (Pixel Perfect 99%).

## 🚀 1. Как запустить проект локально

### Предварительные требования
- **Node.js**: v18.18+ или v20+ / v22+
- **Пакетный менеджер**: `pnpm` (рекомендуется) или `npm`

### Быстрый старт
```bash
# 1. Клонировать репозиторий или перейти в папку проекта
cd kids-paywall-nuxt

# 2. Установить зависимости
pnpm install
# или npm install

# 3. Запустить режим разработки
pnpm dev
# или npm run dev
```

Приложение откроется по адресу: **`http://localhost:3000`**

> **База данных из коробки**: Локально проект использует встроенный SQLite (`file:paywall.db`). Никаких Docker-контейнеров, миграций или внешних сервисов настраивать не нужно — таблица `purchases` создается автоматически при первом обращении.

### Продакшн сборка и проверка
```bash
# Сборка проекта
pnpm build

# Локальный запуск продакшн сервера
node .output/server/index.mjs
```

## 🗄 3. Какую платформу деплоя и БД выбрали и почему

### База данных: SQLite / LibSQL с автоматической адаптацией под Serverless
- **Почему LibSQL / SQLite**:
  1. **Универсальность**: один и тот же клиент `@libsql/client` работает локально с файлом `file:paywall.db` без сетевых задержек, а при подключении облачной базы (Turso) — через `DATABASE_URL` по протоколу HTTP/WebSockets.
  2. **Serverless-ready**: на Vercel движок автоматически направляет локальное файловое хранилище в директорию `/tmp`, обеспечивая стабильную работу бессерверных функций без сбоев прав доступа `EROFS`.
  3. **Легковесность**: компактная схема (`offerId`, `deviceId`, цена, валюта, статус, дата/время) не требует тяжелых ORM вроде Prisma, что обеспечивает мгновенный холодный старт (Cold Start < 50ms).

### Платформа деплоя: Vercel
- **Почему Vercel**:
  1. **Нативная поддержка Nuxt 4 и Nitro**: движок Nitro автоматически определяет окружение Vercel и собирает оптимизированные Serverless Functions без ручной настройки конфигураций.
  2. **Полноценная работа серверных маршрутов (`/api/*`)**: все эндпоинты (`/api/offers`, `/api/purchase`, `/api/restore`) функционируют как независимые бессерверные API-эндпоинты с быстрой обработкой запросов.
  3. **Автоматический CI/CD и Edge Network**: мгновенный деплой по пушу в ветку `main`, автоматический SSL-сертификат, глобальный CDN для статических ассетов и шрифта Nunito с минимальным TTFB.

## 🤖 4. Какие AI-инструменты использовали и что проверили сами

### Использованный AI-инструмент:
- **Google Antigravity** на базе модели **Gemini 3.8 Flash**.

### Что выполнял AI:
- Первичная генерация каркаса компонентов на Vue 3 Composition API по заданным дизайн-токенам.
- Проектирование векторной SVG-графики маскота и фирменных иконок приложения в стилистике детских развивающих игр.
- Написание серверных маршрутов Nitro (`GET /api/offers`, `POST /api/purchase`, `POST /api/restore`) и схемы базы данных.

### Что проверено и доработано вручную:
1. **Pixel Perfect & Mobile-First**: проверено поведение на мобильных экранах от 360px до 430px (iPhone SE, iPhone 14/15/16, Pixel 7) — отсутствие горизонтального скролла, touch targets $\ge 48\text{px}$, безопасные отступы под домашний индикатор iOS (Safe Area).
2. **Типобезопасность (TypeScript)**: строгая типизация запросов/ответов API и контрактов пропсов компонентов без использования типа `any`.
3. **Обработка состояний (Edge Cases)**:
   - Skeleton Loading при первоначальной загрузке тарифов.
   - Защита от повторного клика (Disabled + Spinner состояние кнопки CTA при оформлении покупки).
   - Интерактивный тумблер теста ошибок (иконка жука в шапке) для быстрой проверки экрана сбоя сети.
   - Персистентное сохранение покупок и их успешное чтение при вызове «Восстановить покупки».
4. **Консистентность фавикона и ассетов**: генерация полного набора фирменных иконок (SVG, ICO, Apple Touch Icon) и устранение стандартного логотипа Nuxt в QR-кодах и превью браузера.
5. **Оптимизация сборки**: `pnpm build` выполняется без предупреждений, Nitro генерирует компактные серверные чанки для Vercel Serverless.

## ⏱ 5. Что бы сделали следующим шагом, если бы было ещё 2 часа

Если бы на задачу было выделено ещё 2 часа, я бы реализовал:
1. **Интеграция с нативным WebView (JSBridge)**:
   - Двустороннее общение с iOS (WebKit MessageHandler) и Android (JavascriptInterface) для вызова нативного окна подтверждения покупки Apple In-App Purchase / Google Play Billing.
   - Тактильный отклик (Haptic Feedback) через Web Vibration API или вызов нативного вибратора при переключении тарифов.
2. **A/B тестирование (Remote Config)**:
   - Возможность динамически менять порядок тарифов, тексты бейджей («Скидка 70%» vs «3 дня бесплатно») и цвета CTA-кнопки по параметру конфигурации из базы данных.
3. **Родительский контроль (Parental Gate)**:
   - Всплывающее математическое или логическое задание для родителей («Решите: 12 + 7») перед переходом к экрану оплаты, как того требуют гайдлайны детской категории App Store (Kids Category Guidelines).
4. **Интернационализация (i18n)**:
   - Добавление локалей (EN, ES, DE, JA, ZH) с автоматическим форматированием валют (`Intl.NumberFormat`).
5. **E2E и компонентные тесты (Playwright / Vitest)**:
   - Автотесты полного пользовательского сценария: выбор тарифа $\to$ клик CTA $\to$ валидация записи в БД $\to$ отображение модалки успеха.
